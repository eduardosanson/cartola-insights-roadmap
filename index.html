Fase 4a — Contas e Autenticação

concluída · mergeada em main

Novo contexto app/contexts/contas/ no backend: registro, login com sessão via cookie httpOnly, API tokens pessoais (bearer, revogáveis) e proteção por papel admin nas rotas que antes estavam completamente abertas.

11tasks TDD
259testes passando
99%cobertura
3rodadas de correção
7achados corrigidos na revisão final
  • Tokens opacos, não JWT. Sessão e API token são strings aleatórias com hash SHA-256 no banco — evita gerenciar chave de assinatura e o problema de revogação de JWT.
  • Sessão e API token são credenciais independentes. Revogar o token de API não derruba a sessão web; fazer logout não invalida os tokens usados pelo MCP.
  • Emissão/revogação de token exige cookie de sessão, não bearer. Achado na revisão final: um bearer vazado não pode se auto-renovar nem impedir a própria revogação.

Fase 4b — API Pública

planejado · aguardando execução

CORS por variável de ambiente (aceita a origem de produção sem tocar código) e rate limiting — geral em toda a API e mais restrito em /contas/login//contas/registro contra força bruta e spam de conta. Os endpoints de leitura continuam sem exigir credencial — decisão de produto já fechada na Fase 4a. Publicar a porta da API na internet fica fora desta fase (decisão de infraestrutura separada).

Fixture global que zera o contador do limiter antes de cada teste — sem isso, os testes existentes de login/registro compartilhariam contador (mesmo IP fake do TestClient) e ficariam frágeis à ordem de execução.

Visualização Avançada — o caminho até o visual da POC

Fase 3 · 3 de 5 sub-fases na main

A POC original (dados fictícios, validada antes do schema real) provou três telas que o MVP web de hoje ainda não tinha: radar de atributos por jogador (4 indicadores reais — pontuação média, disciplina e dois específicos do grupo de posição, raio-X de confronto (jogador × mando × o que o adversário costuma ceder) e perfil de risco (o quanto a pontuação do jogador depende de scouts de retorno direto — gol/assistência — versus scouts de participação). Essa trilha não depende da Fase 4a nem da 4b/5 — só da fundação de dados já pronta desde a Fase 2.

As 5 sub-fases

3a
backend

Percentis por posição

Cada atleta ganha o percentil dos scouts relevantes à própria posição, comparado só com os demais da mesma posição — a base numérica que o radar (3b) consome. Entregue com corte mínimo de 5 jogos, empates preservados e cálculo idempotente para GOL, ZAG, LAT, MEI e ATA. A validação real materializou 477 atletas.
